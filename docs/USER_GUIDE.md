# StudyTrail — User Guide

A personal study coach that uses an AI model to choose tools, inspect your quiz
results, search your notes, and prepare your next practice session.

Built for someone learning Python and agentic AI. The first version runs in your
terminal, so you can follow the complete flow without learning a web framework.

**You can try the offline demo immediately. Configure your API key later.**

[Back to the main README](../README.md)

## What you can do

- Ask for a short explanation, a study plan, or a practice quiz.
- Let the live agent inspect your saved scores before recommending practice.
- Search the included Python notes and your own Markdown/text notes.
- Answer multiple-choice quizzes and see explanations after submission.
- Keep progress between sessions in a local SQLite database.
- See tool names as they run, and inspect the small Python implementation.

## Requirements

- Windows PowerShell and [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Python 3.12, which uv can obtain when necessary.
- For live AI only: a Groq API key on the **Free plan**, with available request/token
  quota. No GPU or OpenAI API account is needed. Do not upgrade to the paid Developer
  plan if you want to stay within free usage.

The local environment is `.venv` inside `C:\CLAUDE_env\Study_Agent_python`.
Dependencies are installed there, not into the system Python installation.

## Quick start: no API key

Open PowerShell:

```powershell
cd C:\CLAUDE_env\Study_Agent_python
uv sync --locked
uv run python -m study_agent demo
```

The demo asks three fixed questions about Python loops. Enter `A`, `B`, `C`, or `D`
for each. You receive your score and explanations after all answers are submitted.
Enter `Q` during a quiz to leave without recording an attempt.

The demo exercises the actual local tools and storage, but its sequence and quiz
are predefined. **It is not a live AI agent and makes no model calls.** Demo results
are stored separately from real study results.

You do not need to activate `.venv`; `uv run` uses the project environment.

## Configure the API when you are ready

1. Create an API key in [Groq Console](https://console.groq.com/keys) and stay on the
   Free plan. If you already have a `.env` file, edit it directly and skip the copy step.
2. Copy the example settings once:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. Fill in the values locally:

   ```dotenv
   GROQ_API_KEY=your-real-key-goes-here
   GROQ_MODEL=openai/gpt-oss-120b
   ```

4. Save the file, then check and launch:

   ```powershell
   uv run python -m study_agent doctor
   uv run python -m study_agent chat
   ```

`doctor` reports whether a key is present; it does not verify the key or call the
API. The first `chat` request tests the actual connection. The model is configurable;
choose one your Groq project can access with Chat Completions tool-calling support.
The default is GPT-OSS 120B hosted by Groq. The `openai/` model prefix
identifies the model developer; it does not route requests to OpenAI. Free usage has limits that vary by model
and account. Check your [Groq limits](https://console.groq.com/dashboard/limits).

Never paste your key into chat, commit it, or include it in screenshots. `.env` is
ignored by Git. If the file already exists, edit it rather than copying over it.
Environment variables already set in PowerShell take precedence over `.env`.

## Your first live session

Run `uv run python -m study_agent chat` and enter:

```text
Help me practise Python loops with three beginner questions.
```

A typical session looks like this; wording and tool choices are generated by the model:

```text
You: Help me practise Python loops with three beginner questions.
  Tool: get_scores
  Tool: search_notes
  Tool: create_quiz
Coach: Your quiz is ready. Let's work on range and loop control.
Quiz ready: <quiz-id>
Take it now? [y/N]: y
```

After answering, try:

```text
Review my scores and suggest what I should practise next.
Explain the difference between break and continue using my notes.
Create a three-day plan to improve my weakest topic.
Quiz me on functions with two questions.
```

Chat commands:

- `/scores` displays your results without an API call.
- `/pending` lists saved quizzes you have not completed.
- `/quit` exits the chat.

The last three completed exchanges are retained in memory during one chat session.
Restarting the app clears chat history. Quizzes and scores remain in SQLite.

## Other commands

Run these from the project directory:

```powershell
# Explain all available commands.
uv run python -m study_agent --help

# Check configuration without contacting the API.
uv run python -m study_agent doctor

# Send one live request; this needs your API key.
uv run python -m study_agent ask "Suggest a short plan based on my scores"

# Read real progress, or list unanswered quizzes.
uv run python -m study_agent scores
uv run python -m study_agent pending

# Replace QUIZ_ID with an ID printed by the application.
uv run python -m study_agent quiz QUIZ_ID

# Search notes without an API key.
uv run python -m study_agent notes "loops range"

# Inspect the separate demo progress.
uv run python -m study_agent scores --demo
uv run python -m study_agent pending --demo
uv run python -m study_agent quiz QUIZ_ID --demo
```

For an unfinished demo quiz, include `--demo` when resuming it. Quitting a quiz
discards partial answers but keeps the quiz, so resuming starts at question one.
Each quiz can be submitted once; ask for a new quiz to practise again.

## Add your own notes

Create a UTF-8 `.md` or `.txt` file under `notes/`. No import command is needed.
For example, add `notes/private/my-python-notes.md`, then run:

```powershell
uv run python -m study_agent notes "dictionaries"
```

The `notes/private/` directory is excluded from Git. Included example notes are
tracked. Plain text and Markdown are supported; PDF, images, and Word files are not.
Files larger than 200 KB are skipped in this introductory implementation.

Retrieval ranks passages by matching keywords, returning up to four passages with
file names and line numbers. It does not use embeddings or a vector database.
This provides a small retrieval-assisted teaching flow you can inspect and extend.

## What makes it agentic?

In live mode, the language model decides which allowed tool to call next. Python
validates its arguments, executes the tool, sends the result back, and lets the
model choose another step or provide its final answer.

```text
Your study request
        |
        v
Model chooses a tool or final answer
        |
        +--> get_scores ----> saved quiz performance
        +--> search_notes --> matching local passages
        +--> create_quiz ---> a saved quiz
        |
        v
Tool result returns to the model
        |
        v
Final guidance + optional quiz
        |
        v
You answer --> Python grades --> save_result --> local SQLite
```

The live tool order is chosen by the model; the diagram is a conceptual flow.
`save_result` is deliberately an application function, not a model-callable tool.
The model cannot supply an invented score. Python compares the learner's selected
answers with the stored answer key. The answer key itself is model-generated in
live mode and can still contain mistakes; review explanations critically.

The loop stops after at most six model requests or ten tool calls per user request.
Each request can create one quiz with up to five questions. Tool output errors are
returned for correction; API and storage failures are surfaced rather than hidden.

## Project structure

```text
Study_Agent_python/
|-- study_agent/
|   |-- __main__.py      # python -m study_agent entry point
|   |-- cli.py           # commands, chat, and quiz interaction
|   |-- agent.py         # model/tool loop and coaching instructions
|   |-- tools.py         # tool schemas, validation, and dispatch
|   |-- models.py        # Pydantic models for generated quizzes
|   |-- storage.py       # SQLite quizzes, grading, and results
|   |-- notes.py         # local keyword retrieval
|   |-- config.py        # .env configuration
|   `-- demo.py          # explicit offline demonstration
|-- notes/               # example learning material
|-- tests/               # offline behaviour and integration tests
|-- .github/workflows/   # test workflow for a future GitHub repository
|-- .env.example         # safe configuration template
|-- .gitignore
|-- pyproject.toml       # dependencies and tool configuration
|-- uv.lock              # resolved dependencies for reproducible setup
`-- README.md
```

Runtime files are created in `data/` and excluded from Git:

- `study.sqlite3`: live quizzes and actual study progress.
- `demo.sqlite3`: offline demo quizzes and results.

Back up `data/` while the application is closed if you want to preserve your
progress. This is a single-user local app, with no account system or cloud sync.

## Libraries you will learn

- **openai:** a compatible Python client for Groq's Chat Completions API. Despite
  the package name, this app sends requests to `https://api.groq.com/openai/v1`,
  not OpenAI. No OpenAI key is used.
- **pydantic:** checks model-generated quiz data before it is stored.
- **python-dotenv:** loads your local configuration.
- **rich:** makes terminal messages and progress indicators readable.
- **sqlite3, argparse, pathlib, json:** Python's standard library for storage,
  commands, files, and structured data.
- **pytest and Ruff:** test behaviour and check the Python source.

No LangChain, LangGraph, or multi-agent framework is required for this small loop.
You can introduce one later when you have a concrete need for more orchestration.

## Test and check the project

```powershell
uv sync --locked
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

Tests use temporary databases and scripted model responses. They make no paid API
calls and do not touch your real results. They cover persistence, grading, duplicate
submission, bad tool arguments, retrieval, agent continuation, and stopping limits.
They verify application behaviour, not the educational quality of a live model.

After configuring your key, generate one quiz, submit it, restart the app, and ask the
coach to recommend practice from the saved result.

## Git and GitHub

This folder is prepared for version control with a lockfile, tests, a CI workflow,
and a secret/data ignore file. No remote repository or public upload is required
to run it. A license has not been chosen; add one before distributing it as an
open-source project.

To create a local repository yourself, run these from this folder:

```powershell
uv run git init
uv run git status --short
uv run git add README.md pyproject.toml uv.lock .python-version .gitignore .env.example study_agent notes tests .github
uv run git diff --cached --stat
uv run git commit -m "Build personal study agent"
```

Review staged files before committing. Your `.env`, `.venv`, local data, and private
notes should not be included. If you later add a GitHub remote, the included workflow
will run offline checks on pushes and pull requests.

## Troubleshooting

- **`uv` is not recognised:** if this project's environment and dependencies already
  exist, run `& .\.venv\Scripts\python.exe -m study_agent chat` from this folder.
  This uses the existing uv-created environment. For dependency management, install
  uv using its official instructions and reopen PowerShell.
- **Missing API key:** use the demo, or configure `.env` as described above.
- **Authentication failure:** check the key in your local file and whether a
  PowerShell environment variable is overriding it.
- **Model not found (404):** check `GROQ_MODEL` in `.env`. The default is now
  `openai/gpt-oss-120b` on Groq. Llama 3.3 is no longer available to regular accounts.
  Exit with `/quit` and restart after changing settings.
- **HTTP 400/403/404:** check that your chosen model is available to the API project
  and supports Chat Completions tool calling. Keep the printed request ID when
  investigating a provider error.
- **Quota or rate limit:** wait for your Groq Free plan quota to reset. Check the
  Groq limits page. You do not need to upgrade to a paid plan.
- **No matching notes:** try a short topic keyword and check the file encoding/type.
- **Quiz not found:** confirm the ID and use `--demo` for a demo quiz.
- **Agent limit reached:** ask for one topic and two or three questions. A quiz may
  already have been saved; check `pending` before trying again.
- **uv cache permission error:** use a cache directory you can write to, for example
  `uv --cache-dir .uv-cache sync --locked`.

## Data and costs

Offline commands do not call the model. Live requests send your request, recent
in-session conversation, and tool results (such as score summaries and retrieved
note passages) to Groq. Only add notes you intend to use with that provider.
The app does not execute Python code from the model or provide arbitrary file tools.

Live model use is free within Groq's Free plan limits **when your account is on that
plan**. The app cannot determine your account's billing tier. Upgrading your account
to a paid plan may incur charges; changing the model name does not make a paid
account free. See [Groq billing](https://console.groq.com/docs/billing-faqs).

A single study request can make up to six model requests, each with a 2,400-token
output cap; the SDK may retry a failed request once. Conversation history and tool
schemas also consume token quota, so agent sessions can reach free limits quickly.
On a rate-limit error, wait and retry later. Offline commands and the demo still work.
See [Groq data policies](https://console.groq.com/docs/your-data) for provider retention.

## Suggested learning exercises

1. Read `models.py`, then trace one demo quiz through `storage.py`.
2. Add your own Markdown note and test which queries retrieve it.
3. Read `agent.py` and explain how function calls become ordinary Python operations.
4. Add a tested tool for reading a locally saved study goal.
5. Later, replace keyword retrieval with embeddings and evaluate retrieval quality.
